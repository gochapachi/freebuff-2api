**结论**：工程质量高、验证充分，**无需重构**。v0.10 改进集中为五件事：

1. **【P0】上游模型"策略合同"实时化**：v0.9 的 `ModelMeta` 是静态快照，而上游 freebuff-models.ts 已是**时间窗合同**（availability = always / deployment_hours / off_peak_only + unavailableFallback + efforts 阶梯 + premium 门控）。高峰期 DeepSeek 等模型上游会按时间关闭，网关当前无法预判 → 裸 `model_unavailable`。这是本次核验出的**最大新债务**。
2. **模型目录漂移**：上游已收录 `mimo-v2.5`（免费无限、上游 FALLBACK 落点）与动态模型 `google/gemini-2.5-flash-lite`，网关 HARDCODED_MODELS/MODEL_META_ROWS 未覆盖；README 能力表述需同步。
3. **面板可访问性/体验**：全面板 0 个 ARIA 属性、无键盘导航管理、实时日志无 aria-live；触控目标/对比度未审计。功能已全，**无障碍是"最后一公里"**。
4. **质量门禁收紧**：CI 覆盖率门禁仍是 continue-on-error；E2E（tests/*.cjs）未进 CI；文档漂移（计划书 0-项目全景停在 v0.7.3、API_GUIDE 缺 v0.9 端点）。
5. **发布收尾**：Docker 实跑、自动更新 feed 复验、旧产物清理（desktop/dist 旧 Setup、data/ 测试库、大体积宣传视频策略）。

> 全部为"加法式"修改；默认配置与现行为一致，旧 config.json 免迁移。

## 1. 修复类（P0/P1/P2 · 按优先级）

### 1.1 【P0】上游模型"策略合同"实时化（时间窗 + 动态同步）— 本次核验出的最大新债务

- **证据（上游侧）**：`上游本体（源代码等）/freebuff/common/src/constants/freebuff-models.ts`（4139 行）：
  - `availability: 'always' | 'deployment_hours' | 'off_peak_only'`（L59）；`premium: boolean`（L81）；`multimodal: boolean`（L84）；`reasoningEffort`（L103）/ `efforts`（L117）/ `defaultEffort`（L124）。
  - `freebuffModelUnavailableWindow()` / `freebuffModelUnavailableAt()` 返回"何时恢复"的机器可读 ISO 时间；`resolveAvailableFreebuffModel()` 按当前时间判可用并按 `unavailableFallback` 回落（文件尾部函数区）。
  - DeepSeek 高价窗语义在注释中明示：00:00–10:00 UTC 为高价时段；2026-08-21 起 V4 Flash 行的 availability 已改回 'always' 且带 `unavailableFallback`（L1338-1339 区，注释说明"移除了高峰停服决策"）。
  - `FREEBUFF_MIMO_V25_MODEL_ID`（L167）行 availability='always'、premium=false、multimodal=true，且注释明示 **"MiMo 是唯一 UNLIMITED 行、是 FALLBACK_FREEBUFF_MODEL_ID 的落点"**（L1266-1271）。
  - `KIMI_K3_ECO_MODEL` premium=true（L1694）；`GPT_5_6_LUNA_ES_MODEL` premium=true、displayName='Codex (test)'（L1667-1686）。
- **证据（网关侧）**：`src/models.rs` 的 `MODEL_META_ROWS` 是**静态表**（available 是布尔、无时间窗、无 availableAt）；`refresh_from_upstream` 只同步"模型 id 增删"，不同步策略；表外动态模型（本次冒烟出现 `google/gemini-2.5-flash-lite`，data=20 而 meta=19）默认 `model_available()=true`，会绕过暂停清单。`src/router.rs::resolve/resolve_available` 也不感知时间窗。
- **影响**：a) DeepSeek 高峰/上游部署窗口期，网关仍把模型当可用选给用户 → 上游返回 `model_unavailable`/裸 4xx，体验差且难归因；b) 上游已把部分模型移入 premium 池并门控 `FREE_MODE_PREMIUM_RATE_LIMITS`（freebuff-models.ts L1604-1611 注释），网关若照旧免费调用，等于替用户"裸奔"风控面；c) 面板"今日推荐"排序基于过期的可用性。
- **改法**（复用 models.rs 既有抽象，勿另起炉灶）：
  1. `MetaRow` 增加 `availability: 'always'|'deployment_hours'|'off_peak_only'` 枚举；`available` 改为派生结果（`available = availability==always || 当前在窗口内`），保留布尔字段做向后兼容序列化。
  2. 时间窗函数：DeepSeek 高价窗 00:00–10:00 UTC（按上游注释语义）；deployment_hours 无机器可算时刻 → 该窗口下仅给出可读提示、`availableAt` 返回 null（与上游 `freebuffModelUnavailableAt` 行为对齐，不编造时间）。
  3. 启动 + 定时（建议每 6 小时，可配置）增量同步上游 `freebuff-models.ts`（http 拉取；失败静默降级到静态底座并 warn，**绝不阻断启动**——与现有 `refresh_from_upstream` 同构）。
  4. `resolve()` / `resolve_available()` 先判时间窗；不可用时返回结构化原因 + `availableAt`（ISO）。
  5. `/v1/models` 的 meta 字段增加 `availableAt`/说明文案（data 保持兼容，unknown 字段客户端会忽略）。
  6. 上游快照 vendored 到 `tests/fixtures/freebuff-models.ts` + CI 对比任务（见 1.2）。
- **验收（TDD）**：a) 时间窗函数单测 ≥6（窗口内/外/边界 00:00、10:00、deployment_hours、未知 availability）；b) 同步器 4 用例（成功合并、失败降级 warn、不重复标记、id 增删保留 meta）；c) 路由 3 用例（窗口外拒绝并回落、availableAt 可读、未变模型不抖动）；d) E2E 1 条（Mock 上游 2 个模型：一个窗口外 → /v1/models meta.available=false + fallback 生效）。

### 1.2 【P1】模型目录与元数据全量对齐 + 漂移检测

- **证据**：本次冒烟 `/v1/models` data=20 条（含 `google/gemini-2.5-flash-lite`），meta=19 条（`MODEL_META_ROWS` 全覆盖 HARDCODED_MODELS 的单测成立，但"动态新模型"无 meta）；上游有 `mimo-v2.5`（免费无限、FALLBACK 落点）网关清单缺失；README_zh reasoning_effort 矩阵仍写 `mimo-v2.5`"不支持档位"，但清单里根本没有这个模型 → 文档与实现双重不一致。
- **改法**：a) 决策并收录 `mimo-v2.5`（建议：加入 HARDCODED_MODELS + MODEL_META_ROWS，efforts=None、multimodal=true、premium=false、available=true）；b) 对"动态新增模型"策略定案：表外默认可用（现状）→ 改为"表外默认可用 + 面板标注'未经策略验证'"，或维护一个可编辑白名单；c) 上游快照版本钉住：vendored 到 `tests/fixtures/`，CI 加 diff job，上游变化即 PR 提醒，避免静态表悄悄过期。
- **验收**：meta 表与 vendored 快照一致性脚本（`scripts/check_model_contract.mjs`）通过；`meta_table_covers_all_hardcoded_models` 保持绿。

### 1.3 【P1】面板可访问性基础（WCAG 2.1 A 级起步）

- **证据**：`src/web.rs`（INDEX_HTML，L10-1783）**全文 0 个 `aria-*` 属性**（本次实跑 `HAS_ARIA=False`）；tab 导航是裸 `<button data-tab onclick="showTab()">`（L125-135），无 `role=tablist/tab`、无 `aria-selected`、无键盘左右切换；测试台发送按钮无 loading 的 aria-live 广播；实时日志流无 `aria-live`；只有 `prefers-reduced-motion`（L33）与 920/640 两个 @media 断点（L62/L111），触控目标（44px）未审计。
- **影响**：屏幕阅读器用户无法操作核心流程（导入凭证/测试台/健康看板）；键盘用户 tab 顺序无焦点可见性管理。
- **改法**（渐进式，不重构）：
  1. tab 容器加 `role=tablist`、按钮 `role=tab` + `aria-selected` + `aria-controls`，showTab() 同步属性 + 支持 ←/→ 切换、Home/End；
  2. 实时日志区加 `aria-live=polite`（windowed 渲染保留，只广播新增条数与错误级条目，避免刷屏）；
  3. 全局 focus-visible 样式（当前无 :focus-visible 规则）；
  4. 主要按钮/输入 min 高度 44px（移动端）；
  5. 高对比度：错误红/警告黄对白底对比度过 WCAG AA（4.5:1）逐项核对。
- **验收**：headless Chrome 跑 axe-core（`npx @axe-core/cli http://127.0.0.1:PORT/ui`）A 级 0 严重项；键盘全流程（Tab 顺序 + 左右切 tab + Enter 发送）人工脚本清单 12 项。

### 1.4 【P2】web Cookie 池"全冷却/空池"时的可读降级

- **证据**：`src/web_pool.rs::pick()`（L206-238）全冷却返回 None → 桥接路径直接 401/400 裸错（如 `handle_upload` L5399-5408 返回 `multimodal_requires_web_cookie`）；`snapshot()` 的 `cooldown_until` 是 `"{n}s"` 字符串（L293，`cooldown_str`），面板无法按时间轴展示。
- **改法**：a) 桥接错误统一为结构化 JSON：`{error:{type:'pool_exhausted', message:'所有 web 账号冷却中（n 个），最短约 m 秒后可用', code:'web_pool_exhausted', meta:{cooldown_seconds_min}}}`；b) `cooldown_until` 输出 ISO 时间戳 + 剩余秒两个字段（保留旧字段兼容）；c) 面板健康看板加"预计恢复"排序。
- **验收**：web_pool 单测 +2（全冷却时错误元数据正确、ISO 时间戳解析）；E2E 断言 pool_exhausted 文案。

### 1.5 【P2】请求热路径 panic 面收窄（unwrap 审计）

- **证据**：`src/api.rs` 运行时 unwrap/expect 约 7 处（L286/944/1287/1372/3266/3372/4018 区，其余均在 tests 模块）；`src/memory.rs` 50、`src/skills/store.rs` 45、`src/import.rs` 32、`src/mcp.rs` 27、`src/web_threads.rs` 25、`src/telemetry.rs` 21（多数在测试，但库代码也有）。clippy 零警告不覆盖"panic 风险"。
- **改法**：a) 热路径（chat/messages/桥接/上传）的 unwrap 全部改 `unwrap_or_default`/错误返回；b) 后台写路径（memory/skills/telemetry/import）吞错降级 + warn；c) 加 2 条模糊输入单测（畸形 header/body 不 panic）。
- **验收**：全量 `cargo test` 绿 + clippy 零警告 + 新增 panic 回归用例。

## 2. 体验/功能类（P1/P2 · 可选并行）

### 2.1 【P1】额度"期货视图"：今天还能聊几轮（复用已有数据，零新采集）

- **证据**：上游 `rateLimitsByModel` 每账号今日剩余 + `FREE_MODE_PREMIUM_SESSION_LIMIT=5`（freebuff-models.ts L890，Pacific Day 重置）+ `FREEBUFF_PREMIUM_MODEL_IDS`；网关已有 `account_meta::ModelQuota`（cred_meta.json 缓存）与 `/api/account/overview`（聚合上游 4 端点）、面板总览"今日推荐"卡片（按剩余排序）。
- **改法**：把"剩余次数 × 平均每轮 token 消耗（取最近 7 天 usage 均值）"换算成"今天还能聊约 N 轮"，推荐卡同时标注"该模型在高峰期不可用（availableAt）"。纯前端计算 + 一个聚合端点，不动上游。
- **验收**：E2E 断言推荐卡字段存在且数量合理（无 NaN/负值）。

### 2.2 【P2】凭证自愈"半自动"：冷却即提醒 + 一键重登（不自动重登）

- **证据**：v0.9 已有 401/403 → `mark_cooldown` 10 分钟冷却（web_pool.rs L260-271）与桌面/面板多登录路径；但用户"打开面板才发现全废"。
- **改法**：a) 面板总览加"失效账号"角标（数据已有 `/api/accounts/health`）；b) 桌面托盘气泡提醒（复用 tray.displayBalloon）+ 托盘项"重登失效账号"（打开 WebView2 登录窗）；c) **明确不做**：自动重登（会与上游风控/2FA 冲突，README 已如实披露边界）。
- **验收**：模拟 401 后，health 接口返回失效态 + 面板角标可见；托盘提醒文本正确。

### 2.3 【P2】请求级故障归因"三最"（最慢账号/最常用模型/最高错误率时段）

- **证据**：telemetry.sqlite 已存请求耗时/事件链（TraceRow + event），usage.sqlite 存模型/错误；`/api/usage/cost` 已有 30 分钟滑窗。
- **改法**：`/api/usage/insights` 新增聚合：最慢账号 Top3（TTFT 均值）、最常用模型 Top5、错误率最高时段（按小时）；面板总览一张"三最"卡片。SQL 全部本地聚合，无新依赖。
- **验收**：插入已知样本后断言聚合正确（单测 + E2E 1 条）。

### 2.4 【P2】多模态上传体验补齐

- **证据**：测试台已有拖拽/粘贴/选择上传 + 失败自动降级 base64（v0.9）；缺进度/校验/可读错误。
- **改法**：a) 上传中进度条（XHR 或 fetch 流）；b) 前置校验（类型白名单 jpeg/png/gif/webp、大小 ≤20MB 与 `/v1/uploads` 上限一致、空文件）；c) 失败 toast 复用错误样式；d) 粘贴大图时先压缩（canvas）再上传（省上游额度）。
- **验收**：手测清单 6 项（拖/贴/选/超限/坏类型/无 Cookie）。

### 2.5 【P2】实时日志页增强

- **证据**：windowed 虚拟滚动 v0.8 已实现（>500 条流畅）；缺过滤/暂停/清空/导出。
- **改法**：a) 级别过滤（info/warn/error 高亮）；b) "暂停滚动"（冻结窗口，避免新日志打断查看）；c) 一键导出当前缓冲（JSON/文本，脱敏后——LogBus 已脱敏，导出直接复用）；d) 错误条目计数徽标。
- **验收**：E2E 断言过滤/导出 DOM 行为（本地事件触发，不依赖真实上游）。

### 2.6 【P2】总览"今日推荐"补齐不可用原因

- **证据**：v0.9 推荐卡按 `rateLimitsByModel` 剩余排序（已暂停模型自动靠后）；`router::unavailable_reason`（router.rs）已输出可读原因，但面板未消费。
- **改法**：推荐卡每行附"不可用原因 + availableAt"（消费 1.1 的 meta 扩展）；未验证模型标注"未经策略验证"。
- **验收**：面板 DOM 断言文案出现。

## 3. 工程/质量/流程（P1/P2 · 与功能并行）

### 3.1 【P1】覆盖率门禁收紧（CI）

- **证据**：`.github/workflows/build-release.yml` coverage job 使用 `cargo llvm-cov --fail-under-lines 80` 但 **`continue-on-error: true`**（首次放行收集基线）；本机未装 `cargo llvm-cov`（workflow_status 明示）。
- **改法**：a) 本机 `cargo install cargo-llvm-cov` + 跑出真实基线数字；b) 基线达到 80% 后移除 continue-on-error；c) 若 Windows 上 llvm-cov 不稳定，先只收 `cargo test --test router_test --test web_pool_test` 的覆盖率并设 `--fail-under-lines` 于关键模块（models/router/web_pool/retry/errors）。
- **验收**：CI 绿且覆盖率数字写回 workflow_status 与 CHANGELOG。

### 3.2 【P1】E2E 进 CI（当前只本地跑）

- **证据**：`tests/e2e_phase_v0_9.cjs`（26 断言）、`e2e_phase_v0_8.cjs`（26 断言）、`check_panel_js.cjs` 均不在 CI；CI 只有 cargo test/clippy/fmt + electron-builder。
- **改法**：build-release.yml 增加 job（windows-latest + Node 20）：`cargo build --release` → 起网关（临时端口 + 空配置 + skip_upstream_check）→ `node tests/check_panel_js.cjs` + `node tests/e2e_phase_v0_8.cjs` + `node tests/e2e_phase_v0_9.cjs`（脚本需支持 PORT 环境变量；当前硬编码 47871，见 e2e 脚本）→ 杀进程。Mock 上游场景（router_test）已覆盖真实协议，E2E 只用本地接口断言。
- **验收**：CI 全绿 3 次；e2e 脚本 PORT 参数化后本地也可 47899 复跑。
