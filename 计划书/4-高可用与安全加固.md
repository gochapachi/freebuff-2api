# 4. 高可用与安全加固（v0.8 P1/P2）

> 运行时稳定性 + 安全边界，不改协议层、不重构。

## 4.1 运行时健壮性

| 项 | 现状（证据） | 改进 |
|----|-------------|------|
| 上游会话自动清理 | 已有（`thread_cleanup_loop`，默认 1h/24h） | 保留；`web_threads.json` 绑定表补容量上限 + TTL（见 2.3-#6） |
| 记忆库 WAL | 已启用 | 无改动；备份提示进 README |
| 遥测写入背压 | `TelemetryWriter` 队列 + 丢弃计数 | 面板「体检」已展示 dropped；增加阈值告警（>1000 时面板红色） |
| 请求体上限 | `/v1/uploads` 20MB 显式 | 其余端点无显式 body limit（axum 默认 2MB）——`/v1/chat/completions` 大上下文可能 413；确认客户端行为并给可读错误 |
| 上传 MIME | 已透传 + 扩展名推断 | 加大小/类型统计（已有 kind）；可选 `x-max-upload-mb` 头覆盖 |
| 端口冲突 | start.bat 检测 + 桌面弹窗 | 网关自身启动时对 `listen_addr` 绑定失败给出**明确中文错误**（当前 `?` 上抛 anyhow，信息一般） |
| 优雅退出 | 无 | 加 `SIGINT/SIGTERM` 处理：停止保活循环、等待在途请求（可选，低优先级） |

## 4.2 安全加固（评审：当前防线已较好，补细节）

**已有防线（核验通过，保持不变）**：
- 管理端点鉴权 `admin_authorized`（本机直连 / API Key 双模式）
- CSRF 防线 `origin_allowed`（浏览器 Origin 白名单，含扩展 Origin）
- 非本机监听强制 api_keys（config validate 硬校验）
- 请求密钥脱敏（`x-api-key`/authorization → `sk***…`）
- 上传错误体截断（防泄露内部细节）
- 面板 API Key 仅存 localStorage

**建议补强（P2）**：

| 项 | 说明 |
|----|------|
| 令牌轮换 | 面板生成的 API Key 支持「轮换」：生成新 Key 后**保留旧 Key 60s 宽限期**再移除，避免切换瞬间 401 |
| 面板 CSP | 内嵌页加 `Content-Security-Policy: default-src 'self'`（当前无 CSP 头）；本地面板无外部资源，可直接收紧 |
| 安全响应头 | `/ui`、`/healthz`、`/v1/*` 响应统一加 `X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`（轻量，不动现有逻辑） |
| 上传 MIME 白名单 | 当前透传任意 content-type；建议对「文本注入型」MIME（html/svg）拒绝或转义存储（storageId 仅存存储键，风险低，但 html/svg 作为文档上传可 XSS 到展示端） |
| 凭证脱敏 | `tokens.json` 权限（Windows 继承 ACL 可能过宽）——文档建议放受保护目录；桌面版已在 userData 下，可提示 |
| 日志隐私 | 遥测 `error_excerpt` 可能含用户消息片段；加「日志脱敏开关」`redact_logs`（默认开？默认关需权衡）——**建议默认开启仅脱敏 header/body 中的 token 串** |

## 4.3 配置健壮性

| 项 | 改进 |
|----|------|
| `config.json` 原子写 | 已实现（临时文件+rename，`atomic_write_json`）——保留；新增配置项同样走原子写 |
| 配置校验扩展 | 新增：`listen_addr` 端口合法性、`api_keys` 格式（前缀 sk- 可选提示）、`ad_providers` 合法值白名单 |
| 配置热加载 | 不引入文件 watch（复杂）；仅保留现有"面板写回 + 重启生效"语义；新增项同 |

## 4.4 桌面壳（Electron）加固

| 项 | 现状 | 改进 |
|----|------|------|
| 网关崩溃自愈 | 有（退出自动重启 + 失败弹窗） | 保留；重启间隔 2s 可配 |
| 登录窗口安全 | `nodeIntegration:false, contextIsolation:true` | 已达标；补 `sandbox:true`（Electron 默认安全）+ `webSecurity` 保持默认 |
| 更新链路 | electron-updater 指向 GitHub Release | 保留；加「检查更新失败」时托盘气泡提示（已有 error 事件） |
| 多开 | 无 | 加 `app.requestSingleInstanceLock()`：二次启动激活已有窗口，避免双网关抢端口 |

## 4.5 验收

- [ ] 面板响应头含 nosniff / Referrer-Policy
- [ ] 桌面二次启动聚焦已有窗口、不重复拉起网关
- [ ] 日志/遥测中无明文完整 Cookie（脱敏生效）
