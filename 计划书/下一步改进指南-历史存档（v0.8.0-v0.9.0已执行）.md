2. **上游模型“目录/策略”动态契约缺失**：网关只同步模型增删，不同步 availability 窗口、efforts 阶梯、multimodal 标志、unavailableFallback（本次对照上游源码核验出的新债务）。

5. **质量门禁**：覆盖率门禁、CI 补 fmt、文档数字漂移、旧验收报告归档。
6. **发布收尾**：Docker 实跑、桌面自动更新 feed、宣传资产、旧产物清理。

## 1. 修复类（P0/P1 · 立即可做）

### 1.1 【P1】web Cookie 凭证池化 + 多账号轮询 + 健康评分（优先级最高）
- **证据**：README_zh 明确写“web Cookie 凭证当前由桥接路径使用第一个有效凭证”；`src/api.rs::pick_web_cookie`（L5179）逻辑 = `config.auth_tokens` 里第一个含 `session-token` 的 → 否则导入库 `tokens.json` 里**第一个**匹配项。无健康分、无 401 冷却、无轮询、无账号级故障隔离；`src/pool.rs` 的 Bearer 账号池（评分+熔断三态+指数冷却）完全覆盖不到 web Cookie。api.rs L1521 注释证实“Cookie 塞进 Bearer 池必失败并熔断，web Cookie 由桥接路径使用”。
- **影响**：用户按“浏览器一键登录”导入多个 web 账号后，第一个失效即全链路 401（上游 `free_mode_cli_required`/`auth` 拒绝），面板账号页对 web 账号无健康反馈；与 README 宣称的“多账号自动轮询、健康评分、失败冷却”不符（该宣称只对 Bearer 成立）。
- **改法**（建议复用既有池抽象，勿另起炉灶）：
  1. 把 `ExtractedAuth{kind:"web-cookie"}` 条目纳入一个 `WebCookiePool`（新文件 `src/web_pool.rs`），字段：cookie、稳定 id（现有 `import::cred_id`）、health_score、circuit 三态、cooldown_until、last_error、last_ok_at。
  2. `pick_web_cookie` 改为从池中按“未熔断 + 分数最高 + 冷却期满”挑选；请求失败（401/403/网络）→ 降分/熔断/冷却（复用 `pool.rs` 的 `mark_failure` 语义与 `tier_is_sub` 判定）。
  3. 三条链路统一走池：`/v1/chat/completions` web 桥接（api.rs L830 区）、`/v1/messages` 桥接（L3132 区）、`/api/account/balance`（L334）与 `/api/account/detail`（L2220）。
  4. 面板账号页把 web 账号也渲染进列表（当前只展示 Bearer 池）。
- **验收**：a) 导入 2 个 web Cookie（一号好、二号坏），连续请求全部落好号（Mock 上游验证调用次数）；b) 坏号 401 后进入冷却、日志标注、面板账号状态可见；c) 冷却到期自动恢复；d) 单测覆盖挑选/熔断/冷却/恢复（≥8 用例）。
- **详见**：`6-功能扩展与创新.md §6.3 多上游网关`（抽象 `UpstreamProvider` 是 v1.0 方向，本项是其前 80% 价值）。

### 1.2 【P1】上游模型“目录+策略”动态契约（本次核验出的新债务）
- **证据**：`src/models.rs` 只有静态 `HARDCODED_MODELS` + `refresh_from_upstream`（拉 `CodebuffAI/codebuff/common/src/constants/free-agents.ts`，仅做模型 id 增删）；而本地上游源码 `freebuff/common/src/constants/freebuff-models.ts` 的每个模型行带有 **availability（always/deployment_hours/off_peak_only）、reasoningEffort 阶梯、multimodal 标志、premium、unavailableFallback**，并有 `freebuff-peak-hours.ts`（DeepSeek 高峰窗口 00:00–10:00 UTC 双倍价）、`resolveAvailableFreebuffModel`（关闭时按 fallback 回落）。
- **已发生的漂移例**（上游注释白纸黑字）：GLM 5.3 Flash 默认且 `reasoningEffort` 钉在 `high`、**`max` 已从其阶梯移除**（网关矩阵仍允许 max）；DeepSeek V4 Pro 已撤回（网关清单还挂着）；Muse Spark 1.3 已 404 下架、Ox Alpha/Gemini 3.8 Flash 已暂停但网关清单仍暴露；MiMo 2.5 在上游 UI 由开关门控。
- **影响**：客户端按 `/v1/models` 选到“已暂停/已下架”的模型 → 上游 403/404，网关只透传错误，体验差；efforts 越界才 clamp，阶梯本身与上游不一致。
- **改法**：
  1. `models.rs` 扩展为**模型元数据注册表**：`ModelMeta { id, agent, premium, multimodal, available, efforts: Vec<String>, fallback: Option<String> }`，硬编码底座补全元数据，`refresh_from_upstream` 解析上游 `free-agents.ts` **并可选拉取 `freebuff-models.ts` 的策略行**（同样 GitHub raw）。
  2. 路由层（`router.rs`）在“模型解析→effort clamp→选号”之前加**可用性判定**：不可用模型：a) 返回可读错误（`model_unavailable` + `availableAt` 若上游给了）；或 b) 按 `unavailableFallback` 自动回落并标注。默认 b)（与上游行为一致）。
  3. `/v1/models` 输出带 `multimodal`/`premium`/`availability` 元数据，供面板测试台与推荐逻辑消费。
- **验收**：a) 单测：mock 上游改 availability → 网关跟随（关闭→回落/报错）；b) efforts 阶梯与上游一致（GLM 无 max 等）；c) `/v1/models` 含元数据字段；d) 真实上游冒烟：请求已暂停模型得到可读错误而非裸 403。
- **风险**：上游文件路径可能变动——把 raw URL 收敛为常量并加解析失败降级（保持硬编码底座可用），不要因拉取失败而影响启动。

### 1.3 【P1】reasoning_effort 阶梯与上游对齐
- **证据**：`src/api.rs` L2431 区 `clamp_effort` 静态矩阵（README 表格 low/high/max、low..max、minimal..xhigh）；上游 `freebuff-models.ts` 每行独立阶梯且**阶梯会被运营调整**（GLM 5.3 钉 high/max 移除即例）。静态矩阵必然漂移。
- **改法**：并入 §1.2 的 `ModelMeta.efforts`；`clamp_effort` 读元数据；无 efforts 字段的模型剥离字段（现状逻辑保留）。
- **验收**：单测覆盖“阶梯外降级/无阶梯剥离/与上游对齐表”。

### 1.4 【P1】面板测试台：多模态 + 多轮 + effort + 模型元信息
- **证据**：`src/web.rs` `playSend()`（L520 区）仅构建**单条 user 文本消息**：无图片、无历史上下文、无 reasoning_effort、无 system 提示词、无复制按钮；而网关**已有多模态上传 API**（`/v1/uploads`，api.rs L5069 区，需 web Cookie），面板完全没暴露。
- **改法**（面板 `src/web.rs` 测试台 tab）：
  1. 图片上传：拖拽/粘贴到输入区 → 调 `/v1/uploads`（有 web Cookie 时）或 `/v1/chat/completions` 的 `images` 字段 → 缩略图 + 可移除；无 Cookie 时禁用并提示。
  2. 多轮会话：内存保留 messages 数组，支持“清空会话/复制整段/导出 Markdown”。
  3. effort 下拉：按 `/v1/models` 返回的元数据（§1.2）动态渲染，模型切换联动。
  4. system 提示词输入框（可选，默认空）。
  5. 结果区加“复制”、“重新生成”；发送/停止按钮状态机（已在 v0.8 部分实现，补齐反馈）。
- **验收**：真实浏览器（edge/headless）点一遍：选模型→传图→流式回复→复制；无 Cookie 时图片控件禁用且有提示；320px 不溢出。
- **详见**：`计划书/3-面板现代化方案.md` 的交互规范。

### 1.5 【P2】0.0.0.0 监听时的面板鉴权纵深
- **证据**：`src/api.rs::admin_authorized`（L88）：`api_keys` 为空时仅检查 `is_loopback_request`（**看 X-Forwarded-For/X-Real-IP 头是否存在，并非 TCP 源地址**）；`origin_allowed` 放行本机 Origin。若用户把 `listen_addr` 改成 `0.0.0.0`（README 明确建议“对外提供服务再改 0.0.0.0”）且未配 `api_keys`，**同一局域网直连且不带代理头的客户端可访问面板与管理接口**（改配置/看凭证）。
- **影响**：这属于“配置引导场景下的纵深缺口”，不是默认配置漏洞（默认 127.0.0.1 + 无 XFF 才放行）。评级 P2，加提示为主、默认不改行为。
- **改法**：
  1. 设置页把 `listen_addr` 改为 `0.0.0.0` 时，弹强确认（“局域网可见；请同时设置 API Key”）；
  2. `is_loopback_request` 增加**真实 TCP 源地址**判定（`ConnectInfo` + `SocketAddr`，仅当 `peer.ip().is_loopback()` 才算本机）——不改默认行为，仅收紧 0.0.0.0 场景；
  3. 健康体检（`/api/doctor`）增加“监听非回环但未配置 api_keys”的警告项。
- **验收**：绑定 0.0.0.0 + 无 key：本机可访问；模拟远端 peer（非回环地址构造请求）被 401/403（Router 测试）；面板提示可见。

### 1.6 【P2】旧验收/交付文档归档 + 数字修正
- **证据**：`README.md` L103 写“236 单测”，实测 **238**；`FINAL_ACCEPTANCE.md`/`DELIVERY_SUMMARY.md`/`ROUND2_SUMMARY.md` 是 **v0.1.0 时代**旧稿（端口写 8787、单测 19、模型 20 等），与 v0.8.0 现状严重不符，易误导接手 AI。
- **改法**：README 测试数字改 `238 + 8 + 10`；把三份旧报告移入 `docs/archive/` 并注明“v0.1.0 历史”；`workflow_status.md` 顶部补“v0.9 执行中”（或由落地 AI 在 Phase L 收尾时更新）。
- **验收**：`rg "236|8787" README*.md docs` 无残留；归档目录存在。

## 2. 优化类（P1/P2 · 体验与运营）

### 2.1 账号健康看板（P2）
- **证据**：`6-功能扩展与创新.md §6.2` 已列；账号页（`src/web.rs` account tab）只有列表 + 检查/详情/删除，无熔断/冷却/错误时间线。
- **改法**：复用 `data/account_history.jsonl`（config `account_history_path`）+ telemetry 的账号事件，在账号详情抽屉加时间线（trips/cooldown/429/401/last_error 时序条），按账号聚合“最近错误 Top3”。
- **验收**：注入 20 条假历史 → 时间线正确渲染；无历史时空态文案。注意：web Cookie 账号（§1.1 池化后）也要能进这张表。

### 2.2 模型推荐 + 额度期货（P2）
- **证据**：已有 `/api/account/balance` 的 `rateLimitsByModel`（今日剩余）+ usage 延迟数据（`/api/usage/*`），数据齐备只差展示；`6-功能扩展与创新.md §6.4 创新点1`。
- **改法**：总览页加“今日还能聊几轮”卡片 + “今日最优模型”（剩余额度 × 价格 × 近 30 分钟延迟 综合排序）。“期货”口径必须诚实：按今日剩余×每约 2k token/轮估算，标注“估算值”。
- **验收**：有账号时展示真实估算；无账号时显示引导导入；估算公式单元可测。

### 2.3 全配置导出/导入（P2，换机迁移）
- **证据**：`6-功能扩展与创新.md §6.2`；config+凭证+技能+记忆分散在多个文件，换机全靠手拷。
- **改法**：新增 `POST /api/export`（返回含 config(脱敏后)/tokens/skills 目录/记忆可选 的 JSON 或 zip）+ `POST /api/import`（校验 schema/版本/大小上限后原子写入，凭证加密可选——建议 v0.9 先明文+zstd 压缩，加密列为 backlog）。面板“设置”页加导出/导入按钮，导入前展示将覆盖哪些项并二次确认。
- **验收**：导出→清空 tokens→导入→重启→账号池/技能/记忆恢复一致（E2E 脚本断言）。

### 2.4 请求详情时间线 + “三最”（P2）
- **证据**：`6-功能扩展与创新.md §6.2/§6.4`；遥测已存 TTFT/总耗时/字节/事件链，请求详情页（v0.8 已有）可加。
- **改法**：请求详情加迷你时间线（上游连接→首字节→完成），tag 为“最慢账号/最常用模型/最高错误率时段”三张卡。
- **验收**：单条请求详情渲染时间线；三最数据与 usage 统计一致。

### 2.5 面板交互/可访问性审计项（贯穿）
- 每个可点击控件有反馈（disabled/loading/success/error toast）——现状基本齐，专项过一遍；
- 空态/加载骨架：账号列表、日志、记忆、请求列表均要有（部分已有）；
- 键盘可达：Tab 顺序、`focus-visible`（v0.8 已加）、Esc 关抽屉、Enter 提交；
- 移动端 320px：导航横向滚动已有，检查表格横向滚动与触摸目标 ≥44px；
- `prefers-reduced-motion`（v0.8 已尊重）保持。
- **验收**：headless Edge + 键盘 Tab 走完主要 tab；320/768/1024 断点截图人工核。

## 6. 风险与依赖

- **web Cookie 池（1.1）**：上游对多账号高频轮询可能触发风控。**必须**保持现有“每账号冷却 + 指数退避”语义，默认并发不提升；先 Mock 测试再上真实链路。诚实提示：多账号轮询 ≠ 突破上游限流，文档不得宣称“无限并发”。
- **模型元数据（1.2）**：上游 raw 文件路径可能变动 → 拉取失败必须静默降级到硬编码底座并 warn，**绝不阻断启动**；对上游“暂停但保留”的模型 id，网关应保留识别能力（与上游 `FREEBUFF_PAUSED_FREE_MODEL_IDS` 语义一致）以便给出可读错误而非裸 404。
- **鉴权纵深（1.5）**：加入 `ConnectInfo` 会改变 handler 签名与现有 Router 测试——需要同步更新 `tests/router_test.rs` 的请求构造（用 `TestClient` 直接构造 peer 或 mock）。
- **导出导入（2.3）**：导入凭证会覆盖本机数据——必须二次确认 + 导入前自动备份到 `data/backup-<ts>/`。
- **覆盖率门禁（3.3）**：本机 `cargo llvm-cov` 首次运行可能较慢且受 Windows 影响（fallback：先只加 fmt 门禁，覆盖率 CI 单独 job 且 `continue-on-error` 一版再收紧）。
