# Freebuff2API 项目全景与版本路线图

> 本文件是「计划书」系列的 **入口索引**。其余文档按编号阅读；本文用于回答"这个项目是什么、现在到什么版本了、下一步往哪走"。

## 一、项目一句话

把 Freebuff（codebuff.com）免费层的模型能力**逆向封装**成一个跑在本机的 **OpenAI 兼容 + Anthropic 兼容** 网关，让 Claude Code / Cursor / LobeChat 等任意客户端都能白嫖免费模型。

## 二、当前真实版本基线（证据为本）

## 三、能力地图（已实现）

```
客户端层        Claude Code / Cursor / Codex / LobeChat / NextChat / Cherry Studio / 任意 OpenAI SDK
                  │  OpenAI /v1/chat/completions     Anthropic /v1/messages     /v1/models
                  ▼
网关层(47821)    路由解析 → 模型降级链 → 提示词/技能roster/记忆注入 → 双桶并发 → 多账号池
                  │                                                              │
                  ├─ 账号池：健康评分+熔断三态+指数冷却+换号重试(首字节前)           ├─ web Cookie 桥接
                  │                                                              │   会话 thread 复用
                  ├─ 会话层：排队→活跃→45s心跳→广告换额度保活                     │   续聊只发增量
                  │                                                              ▼
                  ├─ 遥测/用量/日志/记忆/技能/凭证/账号全貌/MCP/体检               上游 codebuff.com
                  └─ 登录链路：内嵌WebView2 → 浏览器扩展 → 剪贴板 → 手动导入
```

**八大支柱（均已实测）**：
1. 双协议出口（OpenAI / Anthropic 流式+非流式，双向协议转换）
2. 多账号智能轮询（评分+熔断+冷却+换号，Claude 路径尚未接入重试）
3. 双桶并发信号量（README 宣称已实现，**代码中未找到实现 → 见疑点 1**）
4. 会话保活 + 广告换额度
5. 记忆层（零 LLM 规则，默认关闭，面板热切换）
6. 技能系统（文件真相源 + roster 注入 + 质量门）
7. 三登录路径（WebView2 内嵌 / 扩展 / 剪贴板+手动）
8. 可观测（遥测 SQLite + 实时日志 SSE + 系统体检 + 用量面板）

## 五、关键疑点 / 债务清单（供 v0.8 优先处理）

> 每项都做了代码级核验，不是凭印象。

| # | 疑点 | 证据 | 影响 | 建议 | 状态 |
|---|------|------|------|------|------|
| 1 | **README 宣称的"双桶并发信号量"在代码里不存在** | `rg Semaphore` 零命中；api.rs 转发路径无任何并发限制 | 多账号并发时可能撞上游并发墙，被风控/429 | **落地实现**（见 2-架构加固） | ✅ v0.8 已实现 |
| 2 | **Claude 路径（/v1/messages）没有重试换号** | handle_claude_messages 单次尝试，`let _ = ensure_session(...)` 吞错 | 上游排队/5xx 直接 502，体验差 | 复用 OpenAI 路径的重试循环（见 2） | ✅ v0.8 已实现 |
| 3 | **Claude 路径不上报 usage / 不做记忆 observe** | handle_claude_messages 无 usage_db.record、无 memory.observe | 用量统计漏记；记忆层学习不完整 | 补齐记账与观察 | ✅ v0.8 已实现 |
| 4 | `handle_account_balance` 的候选判定 `t.contains("%3A")` 过宽 | 任何 URL 编码串都会误判成 Cookie | 面板余额查询选错凭证 | 收窄为 session-token 判定 | ✅ v0.8 已收窄 |
| 5 | `ModelRegistry::models_sync()` 只返回硬编码清单 | 注释写着"供路由解析"，实际 resolve 走 async 路径 | 语义漂移，容易误用 | 标注 + 可选改造 | ✅ 已补注释说明 |
| 6 | `desktop/main.js` 的托盘「系统体检」用 `loadURL` 全页跳转 | 加载 `/#doctor` 与 hash 路由不符 | 体检页可能打不开 | 改 `#doctor` hash 或跳转 `/ui#doctor` | ✅ v0.8 已修复 |
| 7 | `/v1/messages` 非流式成功路径无遥测/用量记录 | 直接 `Json(claude_resp)` 返回 | 面板看不到 Claude 非流式请求 | 补齐 | ✅ v0.8 已实现 |
| 8 | `desktop/package.json` 版本停在 0.7.3 但 README 仍写 0.3.0 | README.md 头部"Setup 0.3.0" | 文档失真 | 版本号统一检查 | ✅ v0.8 已统一 |
| 9 | 单测覆盖 219 项但缺路由级集成测试（axum Router + Mock 上游） | tests/ 只有 core_test.rs | 数据面回归风险 | 补 Router 级测试（见 5） | ✅ v0.8 已补（10 用例） |
| 10 | `ThreadMap` 绑定表无过期清理（内存 + web_threads.json 无上限） | web_threads.rs 未见清理逻辑 | 长期运行内存/文件膨胀 | 加容量上限与 TTL 清理 | ✅ v0.8 已加（2000 + 24h TTL） |
